# JARVIS — Implementation Plan (Stage F1: product shell)

> Status: build plan, authoritative for stage F1. Spec: `docs/architecture/frontend-architecture.md`.
> Decision 1.6 (`docs/decisions.md`): the frontend ships alongside the backend — the full product
> IA ships now against the Phase 1 API, every unimplemented section rendered disabled/coming-soon,
> gated by `GET /v1/capabilities`. Supersedes old stage S5.

## Context

Phase 1 is complete: agents CRUD + auto-published immutable versions, blocking `/run` and SSE
`/stream`, executions list/detail/cancel/events (JSON or SSE), conversations, the error envelope,
and the event envelope (ADR 0003) — 150 unit + 27 integration tests green. F1 consumes that
surface and extends the backend with exactly one small addition: `GET /v1/capabilities`.

Acceptance (from the spec, verbatim): *an agent can be created, edited, versioned, run, watched
live (SSE with `Last-Event-ID` reconnect), cancelled, and replayed entirely through the UI; every
disabled section names its enabling stage; no screen renders data the API didn't return.*

## Confirmed decisions

1. **Client generation** — `openapi-typescript` (types only) + `openapi-fetch` (~1KB typed fetch
   wrapper). No generated hooks: TanStack Query stays the sole server-state paradigm. A committed
   snapshot `web/src/api/openapi.json` is regenerated by `make gen-api`
   (`create_app().openapi()` — no DB needed). The backend stays the single schema authority
   (same principle as ADR 0002).
2. **Error handling** — one `ApiError` (status, kind, details, `fieldErrors()` mapping
   `details.errors` loc→msg). 422 → per-field errors in forms; 409 → toast with the server
   message verbatim; 404 → route-level not-found panel. Hand-rolled zustand toast + Tailwind
   `<Toaster/>`; no component library.
3. **SSE client** (`web/src/api/sse.ts`) — `fetch` + `ReadableStream` reader (POST cannot use
   `EventSource`). Frame parser: incremental buffer split on `\n\n`, `:`-comment frames
   (keep-alive) ignored, `data` JSON authoritative. `Last-Event-ID` tracked per frame. On
   stream end *without* a terminal event: reconnect up to 3× (300ms/1s/3s) re-POSTing
   `{input, session_id, run_id}` + `Last-Event-ID`; then park in a `disconnected` state with a
   **Resume** button (the server replays from the DB through the terminal event). Terminal
   event = done. AbortController-driven teardown on unmount.
4. **Run-console projection** — a *pure* `applyEvent(state, ev, cursor)` reducer in
   `stores/runConsole.ts`: builds the timeline (iteration markers, tool-call cards keyed by
   `tool_call_id`, message blocks), buffers `text.delta` into a 50ms flush cycle (cleared on
   terminal/abort), dedupes by `event_id`, folds all three terminals. **Live SSE and replay
   (`GET /executions/{id}/events` JSON) feed the same function → identical rendering.** This
   is the densest test file in the frontend.
5. **Capabilities payload** — all 12 sections (agents, executions, conversations, tools,
   models, workflows, knowledge, evaluations, observability, plugins, triggers, settings);
   every disabled section carries `stage` + one-line summary. Section flags are a module-level
   literal (a fact of what is implemented); `detail` blocks are *derived* at request time from
   the container (registries mirror registries, never hardcode):
   - `agents.detail.strategies` — new `StrategyRegistry.names()` (mirrors
     `ToolRegistry.descriptors()`)
   - `tools.detail.builtins` — real `ToolDescriptor`s; `tools.detail.mcp = {enabled: false,
     stage: "S4"}`
   - `models.detail.providers` — mock / openai_compatible with their declared
     `ModelCapabilities`; `models.detail.defaults` from `Settings` (`mode: "read-only"`)
6. **Capabilities consumption** — `useCapabilities()`: TanStack Query, `staleTime: Infinity`,
   `refetchOnWindowFocus: false`, `retry: 1`. Loading and error are honest full-screen states —
   the nav never renders as if everything were enabled. A typed `sectionRegistry.ts` maps
   key→{title, route}; nav and all 12 routes render from the payload; disabled sections render
   the one shared `ComingSoon` component (name, summary, stage — no bespoke stubs).
7. **Conversations browser** — the API has no list-conversations endpoint and F1 adds no new
   endpoints beyond capabilities, so the session index is derived client-side from
   `GET /v1/executions` (group by `(agent_id, session_id)`, exclude null sessions, page cap
   with an honest "showing first N"). Transcripts come from the real endpoint; a 404 renders an
   honest empty state. A proper list endpoint belongs to a later stage.
8. **Agent editor** — full `AgentDefinition` surface; strategy picker and tool bindings come
   from the capabilities payload, never hardcoded. Save omits **undefined and null** (the PATCH
   route uses `exclude_unset` + `model_copy` without re-validation — explicit nulls are a real
   hazard) and strips client-only fields (`extra="forbid"` everywhere). Delete handles the
   409 has-executions case.
9. **Scaffold** — Vite + React + TS template in `web/`; Tailwind **v4** (`@tailwindcss/vite`,
   CSS-first, no config file); ESLint flat config (template sets + no-`any` in `src/api/`,
   generated file excluded); vitest + Testing Library + jsdom + **msw v2** for REST;
   `@` → `src` alias. Dev proxy `/v1` and `/healthz` → `127.0.0.1:8000` — **no CORS
   middleware**; the proxy is the single seam (a separately-deployed frontend later will need
   CORS on the backend — noted, not built).
10. **Versions tab** — lists from `AgentDetail.versions` (there is *no* versions-list endpoint;
    only `GET /agents/{id}/versions/{n}`); clicking a version fetches its snapshot into a side
    panel. Detail tabs: Definition · Versions · Runs (links to executions filtered by agent) ·
    API access (curl for `/run`).
11. **E2e** — Playwright (user-confirmed): `web/playwright.config.ts` starts Vite via
    `webServer`; the backend is a documented prerequisite (`uv run jarvis serve` against local
    Postgres — no Docker on this machine). One smoke spec: create a mock `function_calling`
    agent → list → run console live SSE → `run.completed` final message → executions detail →
    replay → conversations transcript → every disabled section names its stage. Randomized
    agent name per run; rows are left behind.
12. **Testing strategy** — msw at the fetch layer (exercises the real generated client,
    envelope parsing, and query hooks); SSE is *not* mocked via msw: the frame parser is
    string-fed, `applyEvent` is tested as a pure function, and `connectRunStream` is tested
    against a stubbed `fetch` returning a hand-built `ReadableStream`.

## API surface F1 rides on (verified in code — corrections vs. README)

- Run routes are `POST /v1/agents/{agent_id}/run` and `POST /v1/agents/{agent_id}/stream`
  (resume = `Last-Event-ID` header **plus** `run_id` in the body, same route).
- No versions-list endpoint — `AgentDetail.versions` is the list; `GET
  /v1/agents/{id}/versions/{n}` (int) fetches one snapshot.
- `/v1/executions/{run_id}/events` — JSON by default, SSE when `Accept` contains
  `text/event-stream`; cursor resume via `?after=`.
- SSE frames: `id: <durable cursor>` / `event: <type>` / `data: <event JSON>`; `: keep-alive`
  comment frames exist. The terminal event always ends the stream (ADR 0003).
- `ToolResult.output` is top-level in API JSON (D17); error envelope everywhere (D13/D16);
  secrets are env-var *names* (ADR 0005).

## Risks & deliberate deferrals

- **PATCH null injection** — the route does `model_dump(exclude_unset=True)` → `model_copy`
  without re-validation; explicit nulls can poison the snapshot. The editor omits undefined
  *and* null; tested.
- **`extra="forbid"`** on every API schema — client-only state must be stripped before save.
- **Stream end ≠ run end** — only a terminal event (or Resume) resolves a run; the client
  never infers completion from stream close.
- **Coalescing timer lifecycle** — the 50ms flush must be cleared on terminal and abort.
- **OpenAPI drift** — the snapshot is committed; regenerate with `make gen-api` whenever
  `schemas.py` or a route changes.
- **Deferred**: auth UI (S2), React Flow canvas (S6), optimistic-concurrency draft hash,
  list-conversations endpoint, backend CORS, Playwright beyond the one smoke.
